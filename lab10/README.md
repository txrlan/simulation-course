### Система массового обслуживания M/M/* с усложнениями

Реализовать систему M/M/* с **двумя дополнительными правилами** (ООП).

**Возможные усложнения:**
- ограничение числа приборов (вероятность отказа);
- очередь;
- нетерпеливость заявок;
- требования к ресурсам (детерминированные или случайные).
- GUI или подробное логирование и вывод результатов работы в отдельный файл

### Описание приложения

Приложение предназначено для моделирования работы многоканальной системы массового обслуживания с очередью и возможностью досрочного ухода заявок по истечении предела ожидания ($M/M/c/K$ с детерминированным временем ожидания). Приложение позволяет исследовать поведение СМО при изменении практически всех параметров, используя классические расчеты идеальной СМО в качестве базового ориентира для оценки влияния фактора нетерпеливости на загруженность системы.

**Модуль настройки и управления**  
Пользователь может настраивать следующие параметры через графический интерфейс:
*   **Интенсивность потока ($\lambda$)** — средняя частота прихода новых запросов в единицу времени.
*   **Скорость обслуживания ($\mu$)** — среднее количество запросов, которое один прибор способен обработать за единицу времени.
*   **Количество приборов ($c$)** — число параллельно работающих каналов обслуживания.
*   **Мест в очереди ($K$)** — максимальная вместимость буфера ожидания.
*   **Предел ожидания ($T$)** — фиксированное время, по истечении которого заявка покидает очередь, если не была принята на обслуживание.
*   **Объем выборки ($N$)** — общее число генерируемых заявок в рамках одного эксперимента.

### Вероятностная модель

**Генерация потока и обслуживания**  
Процесс функционирования СМО представляет собой марковский процесс, усложненный правилом детерминированного отброса заявок по времени. Интервалы времени между последовательными поступлениями заявок ($\Delta t_{вх}$) и длительность их обработки одним прибором ($t_{обсл}$) распределены по экспоненциальному закону с параметрами $\lambda$ и $\mu$ соответственно:
$$f(\Delta t_{вх}) = \lambda e^{-\lambda \Delta t_{вх}}, \quad f(t_{обсл}) = \mu e^{-\mu t_{обсл}}$$

В симуляторе генерация этих интервалов выполняется с помощью экспоненциального распределения библиотеки `numpy` (`np.random.exponential`). Момент прихода каждой последующей заявки рассчитывается как кумулятивная сумма интервалов времени относительно текущего события.

**Логика симулятора**  
Моделирование реализовано по принципу событийно-ориентированного симулятора с использованием приоритетной очереди (кучи `heapq`). Заявки идентифицируются своим уникальным порядковым номером (целым числом `req_id`). В системе обрабатываются три типа событий:
1.  **Прибытие заявки (`EV_ARRIVAL`):** Если количество свободных приборов больше нуля (`free_servers > 0`), один прибор занимается, планируется событие ухода (`EV_DEPARTURE`) в момент `current_time + proc_time`. Если все приборы заняты, но длина очереди меньше лимита (`len(queue) < queue_capacity`), идентификатор заявки `req_id` добавляется в список очереди `queue`, а также планируется событие ухода по нетерпеливости (`EV_DROPOUT`) в момент времени `current_time + max_wait_time`. В противном случае заявка отклоняется из-за отсутствия мест. На каждом шаге прибытия также планируется приход следующей заявки, пока счетчик не достигнет лимита выборки $N$.
2.  **Освобождение прибора (`EV_DEPARTURE`):** Прибор освобождается, уменьшая количество заявок в системе. Если очередь не пуста, первая заявка извлекается из начала списка (`queue.pop(0)`) и направляется на обслуживание с планированием соответствующего события `EV_DEPARTURE`. Если очередь пуста, счетчик свободных приборов увеличивается.
3.  **Истечение времени ожидания (`EV_DROPOUT`):** Если в момент наступления события заявка все еще находится в очереди, её ID физически удаляется из списка `queue` с помощью метода `remove()`, уменьшая число заявок в системе (`in_system`) и увеличивая счетчик ушедших заявок (`dropped_count`). Если заявка уже была извлечена из очереди прибором, то попытка удаления вызовет исключение `ValueError`, которое перехватывается и игнорируется (`pass`).

**Теоретические расчеты**  
Приведенная интенсивность нагрузки (коэффициент загрузки) определяется как:
$$\rho = \frac{\lambda}{\mu}$$

Теоретические вероятности нахождения системы в состояниях для стационарного режима идеальной системы $M/M/c/K$ (без учета нетерпеливости) рассчитываются по формулам Эрланга для многоканальных систем с ограниченной очередью:
*   Вероятность нулевого состояния (все каналы и очередь свободны):
    $$P_0 = \left[ \sum_{k=0}^{c} \frac{\rho^k}{k!} + \sum_{i=1}^{K} \frac{\rho^{c+i}}{c! \cdot c^i} \right]^{-1}$$
*   Вероятность нахождения $k$ заявок на обслуживании ($1 \le k \le c$):
    $$P_k = \frac{\rho^k}{k!} \cdot P_0$$
*   Вероятность нахождения $c$ заявок на обслуживании и $i$ заявок в очереди ($1 \le i \le K$):
    $$P_{c+i} = \frac{\rho^{c+i}}{c! \cdot c^i} \cdot P_0$$

Эмпирические вероятности состояний рассчитываются на основе непрерывного времени пребывания системы в каждом состоянии $k$ (когда в системе находилось ровно $k$ требований) относительно общего времени работы симулятора $T_{общ}$:
$$P_k^{эмп} = \frac{T_k}{T_{общ}}$$

### Выводы

1.  **Работоспособность алгоритма и высокая сходимость:** Результаты имитационного моделирования демонстрируют практически полное совпадение с расчетными теоретическими формулами Эрланга при больших объемах выборки. С ростом числа смоделированных заявок $N$ от 1000 до 1 000 000 абсолютная погрешность определения вероятности простоя системы ($P_0$) снижается с $0.0176$ до $0.0000$ (с точностью до четырех знаков после запятой). Это подтверждает корректность работы событийно-ориентированного симулятора и примененных методов расчета вероятностных состояний.
2.  **Анализ влияния фактора нетерпеливости:** При выбранных параметрах ($\mu = 3.0$, $c = 3$) среднее время обслуживания одной заявки составляет всего $1/\mu \approx 0.33$ ед. вр. При этом суммарная скорость разгрузки очереди при полной занятости приборов равна $c \cdot \mu = 9.0$ з/ед. вр. Поскольку среднее время ожидания заявки в очереди оказывается существенно ниже установленного предела терпения ($T = 2.0$), подавляющее большинство требований успевает перейти на обслуживание. Доля ушедших по нетерпению заявок («Ушло») составляет всего $0.1\% - 0.2\%$, из-за чего реальное поведение системы практически полностью эквивалентно идеальной модели СМО $M/M/c/K$.
3.  **Оценка пропускной способности:** В условиях высокой интенсивности входящего потока ($\lambda = 10.0$), превосходящей номинальную производительность каналов обслуживания ($c\mu = 9.0$), система работает в режиме высокой загрузки. Ограниченная емкость накопителя ($K = 10$) приводит к тому, что система стабильно теряет около $13.3\%$ требований из-за переполнения буфера (полный отказ). Успешно обслуживается при этом около $86.6\%$ входящего потока, что наглядно иллюстрирует ограничения пропускной способности СМО при жестком лимите на длину очереди.
